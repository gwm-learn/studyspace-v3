# 加深与重构工作流（细则）

配合 `SKILL.md`。这里是可直接抄用的表格模板和前后对比例子。

## 1. 诊断表模板

逐行填，一行一个缺口。填完它就是施工图。

```markdown
| # | 维度 | 现状 | 目标 | 动作 | 优先 |
|---|---|---|---|---|---|
| 1 | 一句话模型 | 只有标题下一句定义 | 可复述模型 + 3 条关键认知 | 重写 §1 | 高 |
| 2 | 为什么 | 全篇没有"不用会怎样" | 每个机制至少一处 | 在 §3/§6 补 | 高 |
| 3 | 字段表 | 2 列（字段/作用） | 4 列含边界 | 加"坑/边界"列 | 中 |
| 4 | 流程 | 5 行步骤 | 步骤 + 图 + 异常分支 | 新增图 + 异常表 | 高 |
| 5 | 术语 | 8 行，缩写无全称 | 三列全展开 | 重排 | 中 |
```

优先级只分高/中/低：**高 = 影响"能不能看懂"，中 = 影响"能不能照着做"，低 = 影响观感**。时间不够时只做高。

## 2. 章节映射模板

```markdown
| 原章节 | 处理 | 理由 |
|---|---|---|
| `## 1 一句话结论` | 保留，补 text 图 | 结论对，缺可复述模型 |
| `## 2 速览` | 保留 | — |
| `## 3 关键字段` | 保留 + 扩列 | 信息对，缺边界 |
| `## 4 流程` | 拆成 4.1 正常 / 4.2 异常 | 原文只有成功路径 |
| `## 5 状态机` | 重写 | 原文一句话，实际有 4 个状态 |
| （无） | 新增 `## 先分清 N 个概念` | 读者最大混淆点 |
| `## 7 参考` | 合并进 `## 8` | 两个参考节重复 |
```

规则：

- **保留**：内容正确、定位正确，只做措辞与列补齐。
- **扩写**：骨架对但只有结论，补"为什么/边界/反例"。
- **重写**：结构错位（比如把"决策"和"执行"混成一节）。
- **新增**：读者必经的岔路口（概念区分、判断顺序、状态机）。
- **合并/删除**：重复、越界、纯清单。

## 3. 加深手段库（before / after）

### 3.1 补"为什么"——最有效的一条

**Before**

```markdown
EasyMesh 通过 1905.1 报文做全局决策。
```

**After**

```markdown
EasyMesh 通过 1905.1 报文做全局决策。**为什么不用各 AP 自己判断？** 单个 AP 只看得到自己：
"我这信号弱"不等于"隔壁更好"——隔壁可能正满载、可能回程已经断了。只有拿到全局视图的
Controller 才能把"局部最优"换成"全局最优"。
```

判断标准：补完后，读者能回答"如果去掉这一层会怎样"。

### 3.2 表格加边界列

**Before**

| 字段 | 作用 |
|---|---|
| `ft_over_ds` | FT 走 DS 还是空口 |

**After**

| 字段 | 作用 | 边界与误判 |
|---|---|---|
| `ft_over_ds` | FT 走 DS 还是空口 | 两端必须一致；默认值随版本变（23.05 起为 0），照抄旧教程会踩空 |

技巧：给每一列都问一句"它在什么情况下不成立"，答案就是边界列。

### 3.3 只有成功路径 → 加异常分支

**Before**

```markdown
终端收到 BTM 后切换到新 AP，完成漫游。
```

**After**

```markdown
| 现象 | 根因方向 | 处理方向 |
|---|---|---|
| 终端不动 | 忽略 BTM / 拒绝码 / 自身策略不允许 | 调阈值，别指望强制踢 |
| 切了但断流 | 未启用 11r，或 domain 不一致 | 统一 domain，验证 FT 日志 |
| 部分终端无效 | 终端不支持（如 Windows 在 PSK 下不用 11r） | 换 EAP，或接受延迟 |
```

### 3.4 把结论升级成"可复述模型"

**Before**

```markdown
本章介绍漫游的三种辅助协议。
```

**After**

````markdown
```text
终端侧（STA ↔ AP）          AP 侧（AP ↔ AP）
11k 邻居报告  ─┐            1905.1 CMDU
11v BTM 引导  ─┼─ 被调用 ◄─ Controller 决策
11r FT 快速切换 ┘            Agent 执行
```

三个关键认知：两层不是包含关系 / 决策权在终端 / 承载不等于语义。
````

text 图的作用不是好看，是**让读者能用五行字复述整节**。

### 3.5 加"判断顺序"

凡是"排查/选型/走查"类内容，都要给一条①②③的顺序，并写明每步**答错的后果**：

```markdown
| 步骤 | 问什么 | 答错的后果 |
|---|---|---|
| ① 判支持 | 终端支持 11k/v/r 吗 | 不支持就到此为止，再调参数都是白费 |
| ② 判单点 | 单 AP 上生效吗 | 直接查多 AP 会把配置错误当成协议问题 |
| ③ 判一致 | 多 AP 参数一致吗 | 不一致时 FT 静默退化，日志里看不出来 |
```

### 3.6 推论与边界用 blockquote

这是基准笔记的标志性节奏：正文讲机制，blockquote 讲"由此推出什么""哪里不能断言"。

```markdown
> **推论**：入职必须发生在同一广播域——所以"子节点插上没反应"，先查二层可达性，再查凭据。
> **边界**：如果交换机丢弃保留组播，同一广播域也不成立。
> **待验证**：各实现的默认周期不同，具体值以配置文件为准。
```

一篇 400 行的笔记，这类块出现 8–15 次比较自然；超过 25 次说明正文太薄、全靠旁白撑。

### 3.7 状态机与定时器

没有状态机时，**明写"没有"比省略好**：

```markdown
本主题没有连接状态机，只有两个定时器：beacon 周期与密钥生命周期。
```

有状态机时给三样：状态图（text 即可）、状态表（在等什么 / 失败表现）、定时器表（管什么 / 说明）。

### 3.8 反例与失效条件

每个强结论后面加一句"什么时候不成立"：

- "统一 SSID + 11r 就够" → 失效条件：终端不支持 11r，或 AP 间无二层互通。
- "有线回程优先" → 失效条件：布线经过不转发组播的交换机，onboarding 仍然失败。

## 4. 篇幅与拆分

| 情况 | 处理 |
|---|---|
| 8–15 KB | 常规区间，继续加深没问题 |
| 15–20 KB | 先确认是否两个主题混在一篇；能合并的段落合并 |
| > 20 KB 且含两个可独立成篇的主题 | 拆篇：新篇走 `knowledge-refactor`，原篇留摘要 + 链接 |
| 新增内容 < 原文 30% | 多半是注水，回去看诊断表 |

拆分信号：**读者需要"跳着读"**、两半各自有独立的一句话结论、两半的"相邻主题"几乎不重叠。

## 5. 交付报告模板

```markdown
## 主要改动

**结构（N 节 → M 节）**
1. …（一句话说明这节现在回答什么问题）

**图（+k 张）**
- `图NN-xxx.svg`：回答什么问题，放在哪节

## 修正

| 原说法 | 实际 | 依据 |
|---|---|---|
| … | … | 官方文档 / 上游源码 / 规范 |

## 校验

（审计输出 + 链接回归结果 + 图渲染检查）

## 待验证 / 未做

- …
```

报告里**必须**有"修正"一栏：用户拿二手素材来时，最想知道的就是"哪些地方被我改了、为什么"。
