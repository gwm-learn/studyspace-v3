# QCA 平台边界与资料清单

一句话结论：QCA 目录只记录**高通网络 SoC 特有的 QSDK、IPQ 型号、NSS 加速与 ath11k/ath12k 组合**；当前可核对素材只到“名词与零散搭配”级别，启动链、分区和 SDK 版本仍待补。

> 本篇定位：定义 QCA 目录的范围与已知事实，避免把 OpenWrt 通用内容或“听说的高通方案”写成结论。具体数据面机制链接到 [22-OpenWrt](../../20-平台与系统/22-OpenWrt/.readme.md)。

## 1 · 一句话结论

QCA 平台的适配重心与 MTK 不同：**QSDK 版本、NSS 固件/驱动、Wi-Fi 驱动（ath11k/ath12k）三者版本要对齐**，否则常见现象是“系统能起、无线或加速不工作”。

## 4 · 采集清单

1. **身份**：IPQ 型号、板型、QSDK 版本、内核版本、Wi-Fi 芯片型号。
2. **启动**：boot 介质、引导件组成、串口参数、分区表。
3. **SDK**：QSDK 与上游 OpenWrt 的差异、私有包、补丁集。
4. **加速**：NSS 固件版本、驱动、支持的封装（VLAN/PPPoE/IPv6）、与 QoS/抓包的兼容性。
5. **无线**：ath11k/ath12k 固件、board data、信道与功率限制。
6. **升级**：镜像类型、双分区/回滚、恢复方式。

每条记录带“型号 + 版本 + 来源”，并注明是“实测”还是“文档摘录”。

## 5 · 设计取舍与边界

- **为什么单独建 QCA 目录**：QSDK 与 NSS 的版本耦合很强，混在 OpenWrt 通用笔记里会被误当成通用能力。
- **为什么只写到名词级**：现有素材没有启动链和分区事实，继续展开只能靠猜。
- **代价**：短期目录偏薄；换来的是后续补料时不会先删一堆错误结论。
- **不适用**：只查 hostapd/UCI 配置时，不需要进入本目录。
- **合规边界**：QSDK 源码、固件、board data、运营商规范与现网日志不写入仓库。

## 名词解释

> 缩写给出英文全称；非缩写用“—”表示。

| 术语 | 英文全称 | 解释 |
| --- | --- | --- |
| QCA | Qualcomm Atheros | 高通旗下网络与无线芯片品牌，常与 QSDK 一起出现。 |
| QSDK | Qualcomm Software Development Kit | 高通网络平台的 SDK，包含内核、驱动、工具与私有包。 |
| IPQ | Internet Processor Qualcomm | 高通面向网络设备的 SoC 系列命名。 |
| NSS | Network Subsystem | 高通 SoC 内的网络加速子系统，承担转发/加密等卸载。 |
| ath11k | — | 高通 Wi-Fi 6 的 mac80211 驱动名。 |
| ath12k | — | 高通 Wi-Fi 7 的 mac80211 驱动名。 |
| DSA | Distributed Switch Architecture | 把交换芯片每个端口映射为独立网络接口的内核框架。 |
| PPE | Packet Processing Engine | 硬件包处理引擎的通用称呼，具体实现随厂商。 |
| SoC | System on Chip | 把 CPU、内存控制器、外设与网络单元集成到一颗芯片。 |
| SDK | Software Development Kit | 厂商提供的开发包，通常含内核、驱动、工具链与示例。 |
| BSP | Board Support Package | 面向具体板卡的引导、内核、驱动与配置集合。 |
| swconfig | — | OpenWrt 早期交换机配置框架，整颗芯片抽象为单一设备。 |
| VLAN | Virtual Local Area Network | 虚拟局域网，用标签在同一物理网络上隔离广播域。 |
| QoS | Quality of Service | 服务质量，按优先级调度与限速；硬件加速可能绕过 tc。 |
| PPPoE | Point-to-Point Protocol over Ethernet | 以太网点对点协议，常见于宽带拨号接入。 |
| IPv6 | Internet Protocol version 6 | 第六版互联网协议，地址长度 128 位。 |
