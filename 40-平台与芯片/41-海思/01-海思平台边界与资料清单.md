## 1 · 一句话结论

## 4 · 采集清单

拿到一块海思板或一份 SDK 后，按下面顺序采集，避免只记录“能跑”的结论：

1. **身份**：SoC 型号、板型、SDK 版本、内核版本、OpenWrt 版本。
2. **启动**：boot 介质、引导件文件名与偏移、串口参数、DDR 类型。
3. **分区**：`cat /proc/mtd`、DTS 分区节点、环境变量分区、校准数据分区。
4. **外设**：交换芯片与驱动框架、Wi-Fi 芯片与驱动、PON MAC/PHY、LED/GPIO。
5. **升级**：升级镜像类型、写分区的方式、失败后的恢复路径。
6. **性能**：NAT/转发加速能力、Wi-Fi 吞吐、CPU 占用与瓶颈。

每条记录都要带**型号 + 版本 + 来源**；缺一项就标“待验证”。

## 5 · 设计取舍与边界

- **为什么先定边界**：海思平台资料往往混着 SDK 文档、板级配置和运营商需求；不先分层，最后会变成资料堆。
- **为什么不写通用原理**：同一段 netifd 或 netfilter 说明在 MTK/QCA 上同样成立，复制会让两份内容逐渐不一致。
- **代价**：边界笔记本身不提供“马上能用的命令”，价值在于防止写错和重复。
- **不适用**：如果任务只是查 OpenWrt 的 UCI 写法，不需要进入本目录。
- **合规边界**：SDK 源码、原理图、运营商规范、现网日志、客户信息不写入仓库。

## 名词解释

> 缩写给出英文全称；非缩写用“—”表示。

| 术语 | 英文全称 | 解释 |
| --- | --- | --- |
| SoC | System on Chip | 把 CPU、内存控制器、外设与网络单元集成到一颗芯片。 |
| SDK | Software Development Kit | 厂商提供的开发包，通常含内核、驱动、工具链与示例。 |
| BSP | Board Support Package | 面向具体板卡的引导、内核、驱动与配置集合。 |
| DTS | Device Tree Source | 设备树源码，描述板级硬件与分区。 |
| PON | Passive Optical Network | 无源光网络，ONU/ONT 通过分光器接入 OLT。 |
| ONU | Optical Network Unit | 光网络单元，PON 的用户侧设备。 |
| ONT | Optical Network Terminal | 光网络终端，通常指用户侧终结 PON 的设备。 |
| OLT | Optical Line Terminal | 光线路终端，PON 局侧设备。 |
| GPON | Gigabit-capable Passive Optical Network | ITU-T G.984 系列定义的千兆无源光网络。 |
| EPON | Ethernet Passive Optical Network | 基于以太网帧的 PON 方案，IEEE 802.3ah。 |
| CPE | Customer Premises Equipment | 用户侧终端设备，如家庭网关、光猫。 |
| TR-069 | Technical Report 069 | CWMP 远程管理协议，运营商常用的终端管理接口。 |
| CWMP | CPE WAN Management Protocol | TR-069 定义的终端广域网管理协议。 |
| UCI | Unified Configuration Interface | OpenWrt 的统一配置接口。 |
| GPIO | General-Purpose Input/Output | 通用输入输出引脚，用于 LED、按键与复位控制。 |
| LED | Light Emitting Diode | 发光二极管，常用于状态指示。 |
| OEM | Original Equipment Manufacturer | 按品牌方要求生产设备的厂商。 |
| ODM | Original Design Manufacturer | 同时承担设计与生产的厂商。 |
| BootROM | Boot Read-Only Memory | 芯片出厂固化的引导代码，决定第一级引导来源。 |
