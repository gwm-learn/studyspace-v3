## 1 · 一句话结论

“其他平台”不是按厂商名字堆列表，而是按**是否值得单独维护平台差异**来收纳：有稳定板型、SDK、启动件或交换芯片组合的，才建子目录；只有一颗交换芯片的，记在本篇并链接通用 DSA/swconfig 笔记。

## 4 · 采集清单

1. **身份**：厂商、SoC 型号、板型、SDK 版本、内核/OpenWrt 版本。
2. **启动**：boot 介质、引导件、串口参数、分区表。
3. **交换**：芯片型号、上行接口（SGMII/HSGMII 等）、DSA 还是 swconfig、端口映射。
4. **无线**：芯片型号、驱动框架（mac80211 厂商驱动等）、固件与校准数据。
5. **升级**：镜像类型、写分区方式、恢复路径。
6. **判断**：是否值得单独立目；若只有一颗交换芯片，留在本篇并链接通用笔记。

## 5 · 设计取舍与边界

- **为什么保留“其他”目录**：主线平台之外总有零散板型；全塞进 MTK/QCA 会污染主线结论。
- **为什么不按厂商无限建目录**：目录不是厂商名录，只有持续维护价值的内容才值得独立入口。
- **代价**：本篇会长期偏薄；这是“不编造”的代价，不是缺陷。
- **不适用**：已经有主线目录的平台（海思/MTK/QCA/展锐）不要在这里重复。
- **合规边界**：SDK 源码、原理图、运营商规范、现网日志、客户信息不写入仓库。

## 名词解释

> 缩写给出英文全称；非缩写用“—”表示。

| 术语 | 英文全称 | 解释 |
| --- | --- | --- |
| SoC | System on Chip | 把 CPU、内存控制器、外设与网络单元集成到一颗芯片。 |
| SDK | Software Development Kit | 厂商提供的开发包，通常含内核、驱动、工具链与示例。 |
| BSP | Board Support Package | 面向具体板卡的引导、内核、驱动与配置集合。 |
| DSA | Distributed Switch Architecture | 把交换芯片每个端口映射为独立网络接口的内核框架。 |
| swconfig | — | OpenWrt 早期交换机配置框架，整颗芯片抽象为单一设备。 |
| PHY | Physical Layer | 以太网物理层收发器，负责编码与介质接口。 |
| GMAC | Gigabit Media Access Controller | 以太网 MAC 控制器，常作为交换芯片到 CPU 的上行。 |
| SGMII | Serial Gigabit Media Independent Interface | 串行千兆介质无关接口，常用于 MAC 与 PHY/交换芯片互联。 |
| HSGMII | High-Speed Serial Gigabit Media Independent Interface | 高速串行介质无关接口，支持 2.5G 等速率。 |
| OEM | Original Equipment Manufacturer | 按品牌方要求生产设备的厂商。 |
| ODM | Original Design Manufacturer | 同时承担设计与生产的厂商。 |
| VLAN | Virtual Local Area Network | 虚拟局域网，用标签在同一物理网络上隔离广播域。 |
