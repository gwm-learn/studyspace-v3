## 2 · 平台适配六问

换一块板或换一个平台，按顺序回答这六个问题；答不上来的那一项就是本次 bring-up 的主要风险。

| # | 问题 | 要看的东西 | 常见误判 |
| --- | --- | --- | --- |
| 1 | SoC、板型、SDK/内核/OpenWrt 版本是什么？ | 丝印、DTS、`uname -a`、SDK 发布说明 | 只记 SoC 型号，忽略板型与版本 |
| 2 | 从什么介质启动，第一级引导件是什么？ | boot pin/strap、BL2/Preloader、串口日志 | 把“能烧录”当成“启动链已对齐” |
| 3 | 分区与 rootfs 怎么放？ | DTS 分区节点、`/proc/mtd`、UBI 卷 | 照抄别的板子的偏移 |
| 4 | 交换、Wi-Fi、PON 分别由谁驱动？ | DSA/swconfig、mac80211/厂商驱动、PON MAC/PHY | 只看 `ip link` 有没有接口，不看绑定关系 |
| 5 | 有没有硬件加速，开启后牺牲什么？ | flow offload、HNAT/PPE/NSS、驱动日志 | 只测吞吐，不回归 QoS/端口映射/抓包 |
| 6 | 升级失败怎么恢复？ | 双分区、recovery、外部烧录 | 没有救援路径就量产 |

## 4 · 使用与维护

**选型时**

1. 先看第 1 节矩阵，确认候选平台在启动件、SDK、交换/加速、Wi-Fi、PON、升级六项上是否满足需求。
2. 对每个 `待补` 项，转到对应平台子目录看采集清单，确认是“资料缺失”还是“能力缺失”。
3. 进入具体平台笔记，核对版本与板型，不跨平台套用偏移和命令。

**新增平台时**

1. 先判断是否值得独立子目录：有稳定板型、SDK 或外设组合才建；只有一颗交换芯片的记入 [45-其他平台](./45-其他平台/.readme.md)。
2. 在本页矩阵补一行结论，并在平台子目录写正文；本页不展开实现细节。
3. 更新本页“资料完整度”和对应目录的 `.readme.md`。

## 名词解释

> 缩写给出英文全称；非缩写用“—”表示。

| 术语 | 英文全称 | 解释 |
| --- | --- | --- |
| SoC | System on Chip | 把 CPU、内存控制器、外设与网络单元集成到一颗芯片。 |
| MTK | MediaTek | 联发科，本文指其网络与无线 SoC 平台。 |
| QCA | Qualcomm Atheros | 高通旗下网络与无线芯片品牌，常与 QSDK 一起出现。 |
| IPQ | Internet Processor Qualcomm | 高通面向网络设备的 SoC 系列命名。 |
| QoS | Quality of Service | 服务质量，按优先级调度与限速；硬件加速可能绕过 tc。 |
| FTTR | Fiber To The Room | 光纤到房间，家庭全光组网的产品形态。 |
| ONU | Optical Network Unit | 光网络单元，PON 的用户侧设备。 |
| SDK | Software Development Kit | 厂商提供的开发包，通常含内核、驱动、工具链与示例。 |
| BSP | Board Support Package | 面向具体板卡的引导、内核、驱动与配置集合。 |
| DSA | Distributed Switch Architecture | 把交换芯片每个端口映射为独立网络接口的内核框架。 |
| swconfig | — | OpenWrt 早期交换机配置框架，整颗芯片抽象为单一设备。 |
| HNAT | Hardware Network Address Translation | 厂商 SoC 的硬件 NAT/转发单元。 |
| PPE | Packet Processing Engine | 厂商 SoC 的硬件包处理引擎。 |
| NSS | Network Subsystem | 高通 SoC 内的网络加速子系统。 |
| PON | Passive Optical Network | 无源光网络，ONU/ONT 通过分光器接入 OLT。 |
| CPE | Customer Premises Equipment | 用户侧终端设备，如家庭网关、光猫。 |
| FIT | Flattened Image Tree | 用设备树描述的镜像容器，可含 kernel、DTB、rootfs 与校验。 |
| FIP | Firmware Image Package | 用 `fiptool` 打包的固件容器，通常含 BL31 与 U-Boot。 |
